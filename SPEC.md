# Автомонтаж — полная спецификация проекта

Документ написан так, чтобы по нему можно было написать проект с нуля без каких-либо дополнительных объяснений.

---

## Что это и зачем

Система автоматического монтажа видео. Автор записывает экран + вебку пока работает в дизайн-программе (Figma, Photoshop, анимации). Система:
1. Убирает тишину и паузы
2. Находит и удаляет смысловые повторы (когда автор переформулирует одно и то же)
3. Собирает два варианта готового видео: вертикальный 9:16 и горизонтальный 16:9

Результат — ролики, готовые к публикации, без ручного монтажа.

## Входные данные

Файлы хранятся на **Google Drive** в папке `PROJECTS/Автомонтаж/input/`.

Структура папки сессии:

Если экран пишется в 1920×1080 — кроп не нужен (`SCREEN_CROP_Y = 0`).

## Пайплайн обработки (шаг за шагом)

```
Google Drive → rclone sync → input/
                                    ↓
                            concat файлов
                                    ↓
                        Whisper large-v3
                    (sentence-level + word timestamps)
                                    ↓
                        LLM анализ чанками
                    (удаление смысловых повторов)
                                    ↓
                        _split_on_pauses()
                    (удаление тишины внутри сегментов)
                                    ↓
                        FFmpeg рендер ×2
                    (vertical_9min + horizontal_9min)
                                    ↓
                        rclone upload → Google Drive output/
```

### Шаг 1: Конкатенация файлов

Если сессия состоит из нескольких частей (прерывалась запись) — файлы склеиваются через **FFmpeg concat demuxer** без перекодирования (`-c copy`). Если одна часть — конкатенация не нужна.

Результат: `temp/название_screen_full.mp4` и `temp/название_webcam_full.mp4`.

### Шаг 2: Транскрипция (Whisper)

Из видео экрана извлекается аудио (FFmpeg → WAV 16kHz mono).

Модель: **faster-whisper large-v3**, русский язык, `word_timestamps=True`, `vad_filter=True`.

Параметры VAD (Silero):
- `min_silence_duration_ms = 400` — паузы короче 400мс не режут сегмент
- `speech_pad_ms = 200` — буфер 200мс вокруг речи

Дополнительно:
- `condition_on_previous_text=False` — отключает bias (меньше галлюцинаций)
- `hallucination_silence_threshold=2.0` — не повторять текст в паузах > 2с

**Что получается:** список сегментов. Каждый сегмент — речевой блок (примерно предложение):
```python
{
    "index": 0,
    "start": 1.52,
    "end":   14.3,
    "text":  "Итак, давайте нарисуем карточку...",
    "words": [
        {"word": "Итак",     "start": 1.52, "end": 1.8},
        {"word": "давайте",  "start": 1.85, "end": 2.1},
        ...
    ]
}
```

**Вычисление точных границ (`_compute_boundaries`):**

Whisper даёт размытые границы сегментов. Точные границы нужно считать из word timestamps:
- `seg_start = first_word.start - 0.05`  (5мс до первого слова)
- `seg_end = min(last_word.end, last_word.start + 1.5) + 0.15`  (cap 1.5с на слово, +150мс после)
- **Клиппинг:** `seg[N].end` не должен заходить в `seg[N+1].start`

**Важно про клиппинг:** Whisper часто дублирует слово на границе — последнее слово сегмента N появляется также первым словом сегмента N+1. Простой клиппинг `seg[N].end = seg[N+1].start` режет это слово посередине → в видео слышно "граф..." затем "графикой" = заикание. **Правильный клиппинг:** если точка обрезки попадает внутрь последнего слова, откатываем до начала этого слова.

**Дедупликация:** функция `_dedup_consecutive()` — убирает подряд идущие одинаковые слова внутри одного сегмента (пауза < 0.5с между ними).

### Шаг 3: LLM анализ

**Цель:** найти и удалить смысловые повторы. Автор часто переформулирует одну и ту же фразу 2-3 раза — нужно оставить только финальную версию.

**Почему чанками:** 165 сегментов = ~30 минут видео. Один запрос к LLM не справляется — обрабатывает только первые 40 сегментов. Решение: чанки по 30 сегментов.

Параметры чанков:
- `CHUNK_SIZE = 30` сегментов (~4 минуты видео)
- `OVERLAP = 5` сегментов перекрытие (страхует от пропуска повторов на стыке чанков)
- `STEP = 25` (шаг между чанками)
- Для 165 сегментов: 7 вызовов LLM

Каждый чанк отправляется как:
```
Контекст видео: [VIDEO_CONTEXT]

Проанализируй транскрипцию и найди ВСЕ повторы:

[0] 00:01 --- Итак, давайте нарисуем карточку...
[1] 00:14 --- Берём за референс вот такое изображение...
...
[29] 04:12 --- Нажимаю ОК и применяю эффект.
```

Индексы — абсолютные (не меняются между чанками). LLM возвращает:
```json
{"delete": [0, 3, 7]}
```

Все `delete`-множества из всех чанков объединяются через `set.update()`. Затем фильтрация: оставить только те сегменты, чей `index` не попал в `delete_indices`.

**Модель:** `anthropic/claude-sonnet-4-6` через OpenRouter API, temperature=0.2, timeout=120с.

**Контекст видео (`VIDEO_CONTEXT`):**
```
Автор записывает процесс дизайна: сначала создаёт карточку товара (Figma/Photoshop),
затем делает анимацию. Иногда встречаются рекламные интеграции.
Видео должно охватывать весь процесс от начала до конца.
```

**Системный промпт LLM (дословно, не менять):**
```
Ты редактор видео-транскрипций. Твоя задача — найти ВСЕ места где автор повторяет одну и ту же мысль несколько раз подряд, и оставить только финальную попытку.

ОБЯЗАТЕЛЬНО: просмотри КАЖДЫЙ сегмент от первого до последнего. Повторы встречаются по всей длине видео, не только в начале.

Что удалять — все три случая:
1. Автор начинает фразу, останавливается, начинает заново → удалить все попытки кроме последней
2. Два соседних сегмента говорят одно и то же разными словами → удалить первый
3. Сегмент почти дословно повторяет предыдущий → удалить первый

Примеры:
- [1] "Итак, давайте сделаем карточку" → [2] "Итак, давайте нарисуем карточку" → удалить [1]
- [3] "Отправляюсь в синтекс" → [4] "Отправляюсь синтакс дизайн" → [5] "Открываю раздел Design" → удалить [3][4]
- [6] "перед этим перемещу" → [7] "перед этим перемещу" → [8] "перед этим перемещу" → удалить [6][7]
- [9] "набросить несколько тезисов" → [10] "набросить несколько тезисов" → удалить [9]
- [13] "И нажимаю ОК" → [14] "И нажимаю OK" → удалить [13]

Что НЕ удалять:
- Разные шаги одного процесса (это разные действия, не повторы)
- Тема возвращается через несколько минут с НОВОЙ информацией

Формат ответа — строго JSON, без пояснений до и после:
{"delete": [1, 3, 4]}

Где числа — номера в квадратных скобках перед временем.
Если повторов нет — {"delete": []}
```

### Шаг 4: Разбивка по паузам (`_split_on_pauses`)

**Цель:** удалить тишину внутри kept-сегментов. После LLM у нас есть kept-сегменты (sentence-level). Внутри каждого сегмента могут быть паузы — когда автор думает, молчит 1-2 секунды. Эти паузы нужно вырезать.

**Как работает:** для каждого сегмента берём список слов. Находим межсловные паузы >= `PAUSE_CUT_SEC` (0.5с). Каждая такая пауза — граница нового под-сегмента.

Границы под-сегмента:
- `start = first_word.start - 0.05`
- `end = min(last_word.end, last_word.start + 1.5) + 0.15`

После всех под-сегментов — клиппинг (аналогичный `_compute_boundaries`): следующий не должен перекрывать предыдущий, с тем же правилом откатывания до начала слова.

**Результат:** `timeline` — плоский список под-сегментов. Каждый: `{start, end, text, words}`.

### Шаг 5: FFmpeg рендер

Renderer принимает `timeline` и два видеофайла (экран, вебка).

Для каждого сегмента создаётся запись в **concat list**:
```
file '/path/to/screen_full.mp4'
inpoint 1.234
outpoint 5.678
```

FFmpeg читает concat list, нарезает точно по `inpoint`/`outpoint`, применяет filtergraph, кодирует.

Кодек: `libx264`, CRF=23, preset=`ultrafast`, аудио `aac` 192k.

Аудио fade: 0.5с fade-in в начало, 0.5с fade-out в конец.

## Telegram-бот

### Принцип работы

Бот запущен как systemd-сервис на сервере. Отвечает только одному пользователю (`TELEGRAM_ALLOWED_CHAT_ID`).

### Команды и кнопки

| Команда / кнопка | Действие |
|-----------------|----------|
| `/start` | Приветствие, показывает список команд |
| `/sync` или `📥 Sync` | Запускает `rclone sync` с Google Drive. Показывает новые сессии |
| `/sessions` или `📋 Сессии` | Список сессий готовых к обработке. Inline-кнопки для запуска |
| `/status` или `📊 Статус` | Что сейчас обрабатывается, очередь |
| `/cancel` или `⛔ Отмена` | Останавливает текущую обработку (SIGTERM → Restart=always поднимает снова) |
| `/reset` или `🔄 Сброс` | Удаляет output незавершённой сессии (можно запустить заново) |
| `🗑 Output` | Удаляет всё из output/ локально И с Google Drive |

### Очередь

Бот поддерживает очередь. Если нажать на несколько сессий пока одна обрабатывается — они встают в очередь и запускаются автоматически. Кнопка "▶ Запустить все (N)" добавляет сразу все.

При `/sync`:
1. Запоминает текущие сессии
2. `rclone sync gdrive:PROJECTS/Автомонтаж/input ./input --min-age 30s`
3. Сравнивает — показывает новые

После успешного рендера:

## Ключевые архитектурные решения

### Почему sentence-level сегменты (не word-level блоки)

Ранняя версия разбивала транскрипцию на мелкие блоки по словам (пауза >= 0.4с = граница). LLM получал сотни мелких блоков. Это создавало две проблемы:
1. LLM видел отдельные слова, а не полные мысли — плохо находил смысловые повторы
2. Whisper дублирует слово на границе сегментов → два соседних микроблока содержали одно слово → слово рендерилось дважды = техническое заикание

**Решение:** LLM работает с sentence-level сегментами (естественными речевыми блоками от Whisper). Паузы режутся ПОСЛЕ анализа LLM, отдельным шагом `_split_on_pauses`.

### Почему чанки с перекрытием

Полная транскрипция 30-минутного видео — 165+ сегментов. Один запрос к LLM теряет контекст после первых ~40 сегментов и перестаёт находить повторы. Решение: чанки по 30, перекрытие 5 (сегменты 25-29 видны в чанке 0 и чанке 1 — перекрытие страхует стыки).

### Почему Transcriber — синглтон

Модель large-v3 весит ~3GB. Загрузка занимает 30-60 секунд. Создаётся один раз при запуске, держится в памяти, выгружается только сразу после транскрипции (чтобы не занимать RAM во время LLM и FFmpeg).

### Почему rclone, не прямой API Google Drive

rclone — проверенный CLI-инструмент с поддержкой resume, progress, dry-run. Настраивается один раз через `rclone config`. Не нужен OAuth в коде.

## Известные проблемы и как НЕ надо делать

### Заикание слов ("графикой. Графикой.")

**Причина:** Whisper ставит одно и то же слово в конец сегмента N и начало сегмента N+1. Если оба сегмента kept, на границе слышно слово дважды.

**Правильное решение:** при клиппинге — если точка обрезки попадает внутрь последнего слова сегмента, откатываем clip до начала этого слова. Слово полностью уходит в следующий сегмент.

**Неправильное решение:** не надо делать "fuzzy matching" текстов, не надо сравнивать конец/начало соседних сегментов по тексту, не надо удалять слова из word-списков. Проблема решается только правильным клиппингом по таймингам.

### LLM не находит все повторы

**Причина A:** Слишком большой чанк или слишком большое видео — LLM теряет контекст.
**Правильное решение:** уменьшить CHUNK_SIZE или STEP.

**Причина B:** Промпт слишком мягкий.
**Правильное решение:** менять только системный промпт в `_SYSTEM_PROMPT`. Не менять архитектуру.

### git pull падает с конфликтом

**Причина:** кто-то редактировал файлы напрямую на сервере.
**Решение:** `git reset --hard HEAD && git pull`
